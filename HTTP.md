# HTTP

## Определения

**HTTP** (HyperText Transfer Protocol, протокол передачи гипертекста) — протокол прикладного уровня. Клиент отправляет запрос, сервер возвращает ответ. Так загружаются страницы, файлы и данные API.

**HTTPS** — тот же HTTP, но поверх шифрованного канала TLS. Отличие от HTTP в том, что содержимое запросов и ответов нельзя прочитать и незаметно подменить по пути, а сервер подтверждает себя сертификатом.

**Клиент-серверная модель** — способ общения, при котором клиент сам инициирует запрос, а сервер его принимает, обрабатывает и возвращает ответ. Сервер хранит ресурс или выполняет операцию, клиент этим ресурсом пользуется.

**Идемпотентность** — повтор одного и того же запроса не меняет результат сверх того, что сделал первый вызов. Повторный GET только читает данные, повторный DELETE того же ресурса не удаляет ничего нового. POST обычно не идемпотентен: каждый такой запрос может создать ещё одну запись.

## 2.1. Разбор запроса

```http
POST /api/users HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
Content-Length: 58

{"name": "Иван", "email": "ivan@mail.com"}
```

Метод — POST: запрос создаёт нового пользователя.

Путь — `/api/users`.

Версия — HTTP/1.1.

Заголовок `Content-Type` сообщает, что тело записано в формате JSON.

Заголовок `Authorization` передаёт данные для проверки прав. Схема Bearer означает, что дальше указан токен доступа, по которому сервер понимает, кто выполняет запрос.

Тело запроса стоит после пустой строки. Это JSON с именем и почтой нового пользователя: `{"name": "Иван", "email": "ivan@mail.com"}`.

Ответ сервера:

```http
HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/users/42

{"id": 42, "name": "Иван", "email": "ivan@mail.com"}
```

Статус-код 201 Created означает, что сервер создал новый ресурс.

Заголовок `Location` указывает адрес созданного ресурса. Здесь это `/api/users/42`, то есть пользователь получил идентификатор 42.

В теле ответа лежит JSON созданного пользователя: идентификатор, имя и почта.

## 2.3. Свои запросы

Товары расположены по пути `/api/products`, по той же схеме, что пользователи в образце лежат по `/api/users`.

Получить список всех товаров:

```http
GET /api/products HTTP/1.1
Host: example.com
```

Создать товар «Ноутбук» с ценой 50000:

```http
POST /api/products HTTP/1.1
Host: example.com
Content-Type: application/json
Content-Length: 42

{"name": "Ноутбук", "price": 50000}
```

Удалить товар с id=7:

```http
DELETE /api/products/7 HTTP/1.1
Host: example.com
```

Изменить цену товара с id=3 на 45000. Меняется только одно поле, поэтому используется PATCH, а не POST: повтор такого запроса оставляет ту же цену.

```http
PATCH /api/products/3 HTTP/1.1
Host: example.com
Content-Type: application/json
Content-Length: 16

{"price": 45000}
```
