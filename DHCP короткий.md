# Конспект: протокол DHCP

## Назначение DHCP

Каждому сетевому интерфейсу необходимы IP-адрес, маска подсети и дополнительные параметры: адрес шлюза, DNS-сервера, доменное имя и др. Ручная настройка занимает много времени и может привести к повторному использованию одного адреса.

**DHCP (Dynamic Host Configuration Protocol)** — протокол динамической настройки узлов. Он централизованно выдаёт сетевые параметры и предотвращает дублирование IP-адресов. DHCP работает по модели «клиент — сервер»: при подключении клиент отправляет широковещательный запрос, а сервер возвращает подходящую конфигурацию.

## Предшественники DHCP

- **RARP** выдавал IP-адрес по MAC-адресу. Для каждого сегмента требовался отдельный сервер и ручная регистрация MAC-адресов; дополнительные параметры передавать было нельзя.
- **BOOTP** создавался для бездисковых рабочих станций. Вместе с IP-адресом он мог передавать адрес TFTP-сервера и имя загрузочного файла. Поддержка relay позволила одному серверу обслуживать несколько сетей.
- **DHCP** стал расширением BOOTP, устранив необходимость вручную вести таблицы адресов и ограничения на передачу параметров. DHCP-сервер совместим со старыми BOOTP-клиентами, но не наоборот.

## Режимы назначения адресов

DHCP-серверу задают один или несколько пулов адресов одной сети. Возможны три режима:

1. **Ручное назначение.** Администратор заранее связывает конкретный IP-адрес с MAC-адресом или другим идентификатором клиента. Клиент всегда получает один и тот же адрес.
2. **Автоматическое статическое назначение.** Сервер сам выбирает свободный адрес при первом подключении и закрепляет его за клиентом навсегда.
3. **Динамическое назначение.** Адрес выдаётся только на определённый срок — срок аренды. После отключения клиента адрес освобождается и может быть передан другому устройству.

Динамический режим особенно полезен, когда одновременно в сети работает лишь часть пользователей. Например, для 500 мобильных сотрудников, из которых в офисе одновременно находятся не более 50, может быть достаточно пула из 64 адресов.

## Аренда адреса

Администратор задаёт:

- пул доступных IP-адресов;
- срок аренды адреса.

Продолжительность аренды зависит от условий работы. В учебной сети она может быть равна времени занятия, а в постоянной корпоративной сети — нескольким дням или неделям. До окончания аренды клиент пытается её продлить у прежнего сервера. Если сервер недоступен, клиент повторяет запросы и затем обращается к другим серверам. При невозможности продления параметры теряются.

## DHCP Relay

Обычные DHCP-запросы являются широковещательными и не проходят через маршрутизаторы. Поэтому сервер обычно находится в одной подсети с клиентами.

**DHCP Relay** — посредник, который принимает запрос клиента и пересылает его DHCP-серверу в другой сети. Благодаря этому один сервер может обслуживать несколько подсетей. Для повышения отказоустойчивости также может использоваться резервный сервер.

## Получение адреса: DORA

Упрощённый обмен состоит из четырёх основных этапов:

1. **DHCP Discover** — клиент широковещательно ищет доступные DHCP-серверы.
2. **DHCP Offer** — серверы предлагают адрес и остальные параметры.
3. **DHCP Request** — клиент выбирает предложение и широковещательно сообщает о своём выборе.
4. **DHCP Acknowledgement (ACK)** — выбранный сервер подтверждает адрес и срок аренды; остальные серверы возвращают предложенные адреса в свои пулы.

После получения ACK клиент применяет настройки и переходит в рабочее состояние.

## Ограничения динамической адресации

Частая смена IP-адресов создаёт несколько проблем:

- DNS должен постоянно обновлять соответствие доменных имён и адресов;
- усложняются удалённое управление и мониторинг устройств;
- труднее настраивать фильтрацию пакетов и правила безопасности по IP-адресам.

Поэтому статические адреса обычно назначают маршрутизаторам, серверам, принтерам и другим постоянно доступным сетевым устройствам. Динамические адреса удобнее использовать для клиентских компьютеров и мобильных устройств. Для автоматического согласования изменяющихся адресов с доменными именами применяется динамический DNS.

## Итог

DHCP автоматизирует настройку TCP/IP, уменьшает объём ручной работы администратора и позволяет эффективно использовать ограниченный пул адресов. Основные элементы его работы — централизованный сервер, аренда адресов, обмен DORA и DHCP Relay для обслуживания разных подсетей.
